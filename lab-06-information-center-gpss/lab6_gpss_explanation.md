# Подробный разбор кода GPSS и результатов выполнения

## 1. Построчный разбор кода GPSS

### Строка 1: `GENERATE (UNIFORM(1,1,5)),,,1000`

```gpss
GENERATE (UNIFORM(1,1,5)),,,1000
```

**Назначение:** Создание (генерация) транзактов (заявок) в модели.

**Разбор по словам:**

- **`GENERATE`** — команда блока генерации транзактов
  - Это "источник" заявок в системе
  - Периодически создаёт новые транзакты и запускает их в систему

- **`(UNIFORM(1,1,5))`** — функция распределения для интервала между генерациями
  - `UNIFORM` — равномерное распределение
  - Первый параметр `1` — номер генератора случайных чисел (RN1)
  - Второй параметр `1` — нижняя граница интервала (a = 1)
  - Третий параметр `5` — верхняя граница интервала (b = 5)
  - **Означает:** интервал между появлением заявок случайно выбирается из диапазона [1, 5]

- **`,,,`** — три пропущенных необязательных параметра:
  - Второй параметр (пропущен) — модификатор разброса (offset)
  - Третий параметр (пропущен) — смещение времени первой генерации
  - Четвёртый параметр (пропущен) — лимит приоритета

- **`1000`** — пятый параметр: **лимит генерации**
  - Максимальное количество транзактов, которые создаст этот блок
  - После генерации 1000-й заявки блок GENERATE перестаёт работать

**Итог:** Генерировать 1000 заявок с интервалами, случайно распределёнными равномерно от 1 до 5 единиц времени.

### Строка 2: `Enqueue QUEUE QSystemQueue`

```gpss
Enqueue QUEUE QSystemQueue
```

**Назначение:** Постановка транзакта в очередь.

**Разбор по словам:**

- **`Enqueue`** — метка (label) для этой строки кода
  - Используется для ссылок из других частей программы (например, из TRANSFER)
  - Позволяет "прыгнуть" сюда из другого места программы

- **`QUEUE`** — команда блока управления очередью (добавление в очередь)
  - Увеличивает счётчик заявок в очереди на 1
  - Начинает отсчёт времени ожидания для этой заявки
  - Собирает статистику по очереди

- **`QSystemQueue`** — имя очереди
  - Пользовательское имя для идентификации этой конкретной очереди
  - В отчёте будет фигурировать под этим именем
  - Можно было назвать как угодно (например, Queue1, MyQueue и т.д.)

**Итог:** Заявка помещается в очередь с именем QSystemQueue, начинается отсчёт времени её ожидания.

---

### Строка 3: `SEIZE Operator`

```gpss
SEIZE Operator
```

**Назначение:** Захват (занятие) обслуживающего устройства.

**Разбор по словам:**

- **`SEIZE`** — команда блока захвата устройства (facility)
  - Пытается захватить указанное устройство
  - Если устройство занято, транзакт **блокируется** и ждёт освобождения
  - Если свободно, транзакт захватывает его и идёт дальше

- **`Operator`** — имя устройства (facility)
  - Пользовательское имя обслуживающего аппарата
  - В нашем случае это единственный процессор/оператор
  - В отчёте будет показан как FACILITY с именем Operator

**Итог:** Заявка пытается захватить обслуживающий аппарат Operator. Если он занят — ждёт в блокированном состоянии.

---

### Строка 4: `DEPART QSystemQueue`

```gpss
DEPART QSystemQueue
```

**Назначение:** Удаление транзакта из очереди (после успешного захвата устройства).

**Разбор по словам:**

- **`DEPART`** — команда блока выхода из очереди
  - Уменьшает счётчик заявок в очереди на 1
  - Завершает отсчёт времени ожидания для этой заявки
  - Фиксирует время, проведённое в очереди, для статистики

- **`QSystemQueue`** — имя очереди (та же самая, что в QUEUE)
  - Должна совпадать с именем в блоке QUEUE
  - Указывает, из какой именно очереди удаляется заявка

**Итог:** Заявка удаляется из очереди QSystemQueue после успешного захвата процессора (статистика времени ожидания записывается).

### Строка 5: `ADVANCE(NORMAL(1,9,2))`

```gpss
ADVANCE(NORMAL(1,9,2))
```

**Назначение:** Задержка транзакта на время обработки.

**Разбор по словам:**

- **`ADVANCE`** — команда блока задержки
  - Задерживает транзакт на указанное время
  - Имитирует процесс обработки заявки
  - Транзакт "замораживается" на определённое время

- **`(NORMAL(1,9,2))`** — функция нормального распределения для времени обработки
  - `NORMAL` — нормальное (гауссово) распределение
  - Первый параметр `1` — номер генератора случайных чисел (RN1)
  - Второй параметр `9` — математическое ожидание (μ = 9)
  - Третий параметр `2` — среднеквадратичное отклонение (σ = 2)
  - **Означает:** время обработки распределено по нормальному закону со средним 9 и отклонением 2

**Итог:** Заявка обрабатывается в течение времени, случайно выбранного из нормального распределения N(9, 2).

### Строка 6: `RELEASE Operator`

```gpss
RELEASE Operator
```

**Назначение:** Освобождение обслуживающего устройства.

**Разбор по словам:**

- **`RELEASE`** — команда блока освобождения устройства
  - Освобождает ранее захваченное устройство
  - Делает его доступным для других транзактов
  - Обновляет статистику использования устройства

- **`Operator`** — имя устройства (то же, что в SEIZE)
  - Должно совпадать с именем в блоке SEIZE
  - Указывает, какое именно устройство освобождается

**Итог:** Обслуживающий аппарат Operator освобождается и становится доступным для следующей заявки.

### Строка 7: `TRANSFER 0.7,,Enqueue`

```gpss
TRANSFER 0.7,,Enqueue
```

**Назначение:** Вероятностная маршрутизация транзакта (возврат в очередь или завершение).

**Разбор по словам:**

- **`TRANSFER`** — команда блока передачи управления
  - Изменяет маршрут движения транзакта в модели
  - Может быть безусловной, условной или вероятностной

- **`0.7`** — вероятность перехода по первому маршруту
  - Значение от 0.0 до 1.0 (доля, не проценты!)
  - `0.7` означает **70% вероятность**
  - С вероятностью 70% транзакт пойдёт по первому пути
  - С вероятностью 30% (1 - 0.7) — по второму пути

- **`,`** — пропущенный второй параметр (адрес для случая "не повезло")
  - Когда второй параметр пропущен, транзакт переходит к **следующему блоку**
  - В нашем случае — к блоку TERMINATE

- **`,Enqueue`** — третий параметр: метка для перехода (случай "повезло")
  - Ссылка на метку `Enqueue` (строка 2)
  - С вероятностью 70% транзакт возвращается к блоку QUEUE
  - Заявка снова встаёт в очередь для повторной обработки

**Итог:** С вероятностью 70% заявка возвращается в очередь (к метке Enqueue), с вероятностью 30% идёт дальше к TERMINATE.

---

### Строка 8: `TERMINATE 1`

```gpss
TERMINATE 1
```

**Назначение:** Удаление транзакта из модели и уменьшение счётчика завершения.

**Разбор по словам:**

- **`TERMINATE`** — команда блока завершения транзакта
  - Удаляет транзакт из системы (уничтожает его)
  - Уменьшает специальный счётчик завершения на указанное значение
  - Когда счётчик достигает 0, моделирование останавливается

- **`1`** — декремент счётчика завершения
  - На сколько единиц уменьшается счётчик при прохождении транзакта
  - Счётчик задаётся в команде START

**Итог:** Заявка удаляется из системы, счётчик завершения уменьшается на 1. Когда 1000 заявок будут удалены, моделирование завершится.

---

### Строка 9: `START 1000`

```gpss
START 1000
```

**Назначение:** Запуск моделирования с заданным счётчиком завершения.

**Разбор по словам:**

- **`START`** — команда запуска симуляции
  - Это единственная исполняемая команда в GPSS
  - Все предыдущие строки — описание модели
  - START запускает выполнение модели

- **`1000`** — начальное значение счётчика завершения
  - Моделирование будет продолжаться, пока счётчик не достигнет 0
  - Каждый TERMINATE с параметром 1 уменьшает счётчик на 1
  - Когда счётчик = 0, симуляция останавливается

**Итог:** Запустить моделирование. Остановить, когда 1000 заявок будут обработаны и удалены (TERMINATE).

## 3. Физический смысл результатов

### Почему очередь такая большая?

**Причина:** Дисбаланс скоростей генерации и обработки + эффект возврата заявок.

1. **Скорость генерации:**
   - Интервал между заявками: UNIFORM(1, 5)
   - Средний интервал: (1 + 5) / 2 = **3 единицы времени**
   - Интенсивность генерации: 1/3 ≈ **0.333 заявки/время**

2. **Скорость обработки:**
   - Время обработки: NORMAL(9, 2)
   - Среднее время: μ = **9 единиц времени**
   - Интенсивность обработки: 1/9 ≈ **0.111 заявки/время**

3. **Коэффициент загрузки (ρ):**
   - ρ = λ / μ = 0.333 / 0.111 ≈ **3.0**
   - ρ > 1 означает **нестабильную систему**!
   - Заявки прибывают **в 3 раза быстрее**, чем обрабатываются

4. **Эффект возврата (70%):**
   - 70% обработанных заявок возвращаются
   - Это создаёт дополнительную нагрузку
   - Эффективная нагрузка ещё выше!

**Результат:** Очередь растёт неограниченно. Если бы не лимит на 1000 заявок, она бы росла бесконечно.

## 4. Связь с теорией массового обслуживания

Данная модель соответствует системе **M/M/1 с обратной связью**, где:

- **M** — пуассоновский (экспоненциальный) поток (у нас равномерный, но принцип похож)
- **M** — экспоненциальное обслуживание (у нас нормальное)
- **1** — один обслуживающий канал
- **Обратная связь** — вероятность возврата p = 0.7

**Формула для среднего числа заявок в системе (с возвратом):**

```
L = ρ / (1 - ρ) × (1 / (1 - p))
```

где p = 0.7 — вероятность возврата.

При ρ = 3 система нестабильна, поэтому очередь растёт до тех пор, пока генератор не остановится (1000 заявок).
