# Подробный разбор лабораторной работы №7: Информационный центр на GPSS

## Описание задачи

**Моделируется информационный центр** со следующими параметрами:

- **Клиенты** приходят каждые **10 ± 2 минуты**
- **3 оператора** с разной производительностью:
  - Оператор 1 (самый быстрый): **20 ± 5** минут
  - Оператор 2: **40 ± 10** минут
  - Оператор 3 (самый медленный): **40 ± 20** минут
- **Правило выбора:** клиент выбирает свободного оператора с **максимальной производительностью**
- **Отказ в обслуживании:** если все 3 оператора заняты
- **2 компьютера** для обработки запросов:
  - Компьютер 1: **15 минут** (обслуживает запросы от операторов 1 и 2)
  - Компьютер 2: **30 минут** (обслуживает запросы от оператора 3)
- **Цель:** обработать 300 запросов и определить **вероятность отказа**

---

## 1. Построчный разбор кода GPSS

### Строка 1: `GENERATE 10,2,0,300`

```gpss
GENERATE 10,2,0,300
```

**Назначение:** Генерация клиентов (транзактов), приходящих в информационный центр.

**Разбор параметров:**

- **`GENERATE`** — команда генерации транзактов

- **`10`** — **среднее значение (A)** интервала между появлениями клиентов
  - Базовое время между генерациями = 10 минут

- **`2`** — **модификатор разброса (B)** — **половина интервала (spread/modifier)**
  - Интервал варьируется в диапазоне **[A-B, A+B] = [8, 12]**
  - **ВАЖНО:** По умолчанию в GENERATE используется **равномерное распределение**!
  - Формула: `время = A + (2B × R - B)`, где R ∈ [0, 1]
  - Упрощённо: `время = 10 ± 2` минуты (равномерно в диапазоне [8, 12])

- **`0`** — **смещение времени первого транзакта (C)**
  - `0` означает, что первый клиент появляется сразу в момент времени 0

- **`300`** — **лимит генерации (D)**
  - Будет сгенерировано ровно **300 клиентов**
  - После 300-го клиента генератор прекращает работу

**Итог:** Генерировать 300 клиентов с интервалами от 8 до 12 минут (равномерно), начиная с момента времени 0.

---

### Блок операторов: Выбор свободного оператора

Клиенты пытаются выбрать свободного оператора в порядке предпочтения: сначала Оператор 1 (самый быстрый), затем Оператор 2, затем Оператор 3. Если все заняты — отказ.

### Строка 2: `operator_1 GATE NU oper_1,operator_2`

```gpss
operator_1 GATE NU oper_1,operator_2
```

**Назначение:** Проверка доступности Оператора 1 (самого быстрого).

**Разбор по словам:**

- **`operator_1`** — метка (label) для этой строки
  - Точка входа в блок проверки первого оператора

- **`GATE`** — команда условного блока (вентиль)
  - Проверяет условие и либо пропускает транзакт, либо перенаправляет его

- **`NU`** — тип условия: **N**ot **U**sed (устройство не занято)
  - Проверяет, свободно ли указанное устройство
  - `NU` = "Not Used" = "Не используется" = "Свободно"

- **`oper_1`** — имя устройства для проверки
  - Проверяем, свободен ли Оператор 1

- **`,operator_2`** — адрес перехода, если условие **НЕ выполнено**
  - Если Оператор 1 **занят**, транзакт переходит к метке `operator_2`
  - Если Оператор 1 **свободен**, транзакт идёт дальше (к следующему блоку SEIZE)

**Итог:** Если Оператор 1 свободен — занять его, иначе перейти к проверке Оператора 2.

### Строки 3-6: Обслуживание у Оператора 1

```gpss
    SEIZE oper_1
    ADVANCE 20,5
    RELEASE oper_1
    TRANSFER,computer_1
```

**Блок выполняется, если Оператор 1 был свободен.**

**Строка 3: `SEIZE oper_1`**
- **`SEIZE`** — захватить устройство
- **`oper_1`** — имя устройства (Оператор 1)
- **Действие:** клиент захватывает Оператора 1, тот становится занятым

**Строка 4: `ADVANCE 20,5`**
- **`ADVANCE`** — задержка на время обработки
- **`20`** — среднее время обработки (A = 20 минут)
- **`5`** — модификатор разброса (B = 5 минут)
- **Диапазон:** [20-5, 20+5] = **[15, 25]** минут (равномерное распределение)
- **Действие:** клиент обрабатывается у Оператора 1 в течение **20 ± 5** минут

**Строка 5: `RELEASE oper_1`**
- **`RELEASE`** — освободить устройство
- **`oper_1`** — имя устройства
- **Действие:** Оператор 1 освобождается и становится доступным для следующего клиента

**Строка 6: `TRANSFER,computer_1`**
- **`TRANSFER`** — безусловный переход
- **`,computer_1`** — метка назначения (пропущен первый параметр = безусловный переход)
- **Действие:** запрос отправляется на обработку к Компьютеру 1

**Итог:** Клиент обслуживается у Оператора 1 в течение 20±5 минут, затем запрос переходит к Компьютеру 1.

### Строка 7: `operator_2 GATE NU oper_2,operator_3`

```gpss
operator_2 GATE NU oper_2,operator_3
```

**Назначение:** Проверка доступности Оператора 2 (если Оператор 1 был занят).

**Разбор:**

- **`operator_2`** — метка входа в блок проверки второго оператора
- **`GATE NU`** — проверка, свободен ли оператор
- **`oper_2`** — имя устройства (Оператор 2)
- **`,operator_3`** — если Оператор 2 **занят**, переход к проверке Оператора 3

**Итог:** Если Оператор 2 свободен — занять его, иначе перейти к Оператору 3.

- **`RELEASE oper_2`** — освобождение Оператора 2
- **`TRANSFER,computer_1`** — запрос переходит к **Компьютеру 1**

### Строка 12: `operator_3 GATE NU oper_3,fail`

```gpss
operator_3 GATE NU oper_3,fail
```

**Назначение:** Проверка доступности Оператора 3 (последняя попытка).

**Разбор:**

- **`operator_3`** — метка входа в блок проверки третьего оператора
- **`GATE NU`** — проверка, свободен ли оператор
- **`oper_3`** — имя устройства (Оператор 3)
- **`,fail`** — если Оператор 3 **занят**, переход к метке `fail`
  - **КРИТИЧНО:** это означает **отказ в обслуживании**
  - Все 3 оператора заняты → клиент уходит без обслуживания

**Итог:** Если Оператор 3 свободен — занять его, иначе отказать клиенту (переход к метке `fail`).

### Строки 13-16: Обслуживание у Оператора 3

```gpss
    SEIZE oper_3
    ADVANCE 40,20
    RELEASE oper_3
    TRANSFER , computer_2
```

**Аналогично предыдущим операторам:**

- **`RELEASE oper_3`** — освобождение Оператора 3
- **`TRANSFER , computer_2`** — запрос переходит к **Компьютеру 2** (не к Компьютеру 1!)

**Итог:** Клиент обслуживается у Оператора 3 в течение 40±20 минут, затем запрос идёт к Компьютеру 2.

### Строка 17: `computer_1 QUEUE queue_1`

```gpss

```

**Назначение:** Постановка запроса в очередь к Компьютеру 1.

**Разбор:**

- **`computer_1`** — метка входа в блок Компьютера 1
- **`QUEUE`** — добавить транзакт в очередь
- **`queue_1`** — имя очереди

**Итог:** Запрос встаёт в очередь queue_1 к Компьютеру 1.

### Строки 18-21: Обработка на Компьютере 1

```gpss
    SEIZE comp_1
    DEPART queue_1
    ADVANCE 15
    RELEASE comp_1
```

**Строка 18: `SEIZE comp_1`**
- Захватить Компьютер 1
- Если занят, транзакт ждёт в очереди

**Строка 19: `DEPART queue_1`**
- Удалить транзакт из очереди queue_1
- Фиксируется время ожидания в очереди

**Строка 20: `ADVANCE 15`**
- Задержка на **15 минут** (без разброса!)
- **Детерминированное** время обработки

**Строка 21: `RELEASE comp_1`**
- Освободить Компьютер 1

**Итог:** Запрос ожидает в очереди, захватывает Компьютер 1, обрабатывается ровно 15 минут, освобождает компьютер.

### Строка 31: `ending SAVEVALUE nfail,n$fail`

```gpss
ending SAVEVALUE nfail,n$fail
```

**Назначение:** Сохранение количества отказов в переменную.

**Разбор по словам:**

- **`ending`** — метка блока завершения
  - Сюда приходят ВСЕ клиенты (успешные и отказанные)

- **`SAVEVALUE`** — команда сохранения значения в ячейку памяти
  - Сохраняет значение в именованную переменную (SAVEVALUE)

- **`nfail`** — имя ячейки памяти (переменной)
  - Будет хранить количество отказов

- **`,n$fail`** — значение для сохранения
  - **`n$`** — системная функция GPSS: **количество транзактов, прошедших через метку**
  - **`n$fail`** — количество транзактов, прошедших через метку `fail`
  - **Это и есть количество отказов!**

**Итог:** В переменную `nfail` сохраняется количество клиентов, получивших отказ.

---

### Строка 32: `SAVEVALUE prob,((n$fail)/(n$success + n$fail))`

```gpss
    SAVEVALUE prob,((n$fail)/(n$success + n$fail))
```

**Назначение:** Вычисление вероятности отказа.

**Разбор:**

- **`SAVEVALUE`** — сохранение значения

- **`prob`** — имя переменной для вероятности отказа

- **`((n$fail)/(n$success + n$fail))`** — формула вычисления вероятности:
  - **`n$fail`** — количество отказов (транзакты через метку `fail`)
  - **`n$success`** — количество успешных обслуживаний (транзакты через метку `success`)
  - **`n$success + n$fail`** — общее количество клиентов (должно быть 300)
  - **Формула:** `P_отказа = количество_отказов / общее_количество`

**Итог:** В переменную `prob` сохраняется вероятность отказа = (отказы) / (всего клиентов).

---

### Строка 33: `TERMINATE 1`

```gpss
    TERMINATE 1
```

**Назначение:** Удаление транзакта и уменьшение счётчика завершения.

**Разбор:**

- **`TERMINATE`** — удалить транзакт из модели
- **`1`** — уменьшить счётчик завершения на 1

**Механизм работы:**
- Счётчик завершения устанавливается командой START (см. ниже)
- Каждый TERMINATE уменьшает счётчик
- Когда счётчик достигает 0, моделирование останавливается

**Итог:** Клиент удаляется из системы, счётчик уменьшается на 1.

---

### Строка 34: `START 300`

```gpss
    START 300
```

**Назначение:** Запуск моделирования с заданным счётчиком.

**Разбор:**

- **`START`** — команда запуска симуляции
  - Единственная исполняемая команда в GPSS
  - Все предыдущие строки — описание модели

- **`300`** — начальное значение счётчика завершения
  - Моделирование продолжается, пока счётчик > 0
  - Каждый TERMINATE с параметром 1 уменьшает счётчик на 1
  - После прохождения 300 клиентов (успешных или отказанных) счётчик = 0 → STOP

**Итог:** Запустить моделирование. Остановить после обработки (успешной или с отказом) 300 клиентов.

## 3. Физический смысл результатов

### Почему вероятность отказа 23%?

**Причина:** Недостаточная пропускная способность операторов.

**Анализ загрузки операторов:**

Все 3 оператора загружены примерно на **33-35%**:
- Оператор 1: 34.5%
- Оператор 2: 33.8%
- Оператор 3: 31.2%

**Почему при такой низкой загрузке много отказов?**

**Объяснение:**

1. **Клиенты приходят неравномерно** (случайный процесс)
   - Средний интервал: 10 минут
   - Иногда приходят несколько клиентов подряд

2. **Операторы обслуживают долго:**
   - Оператор 1: 20±5 мин (до 25 мин)
   - Операторы 2 и 3: 40±10/20 мин (до 60 мин!)

3. **Нет очередей к операторам!**
   - Если все 3 оператора заняты → **мгновенный отказ**
   - Клиент не может подождать свободного оператора

4. **Правило выбора создаёт дисбаланс:**
   - Все предпочитают Оператора 1 (самого быстрого)
   - Оператор 1 перегружен (121 клиент)
   - Оператор 3 недогружен (51 клиент)

### Почему огромная очередь к Компьютеру 2?

**Причина:** Дисбаланс производительности.

**Анализ:**

1. **Оператор 3** обрабатывает запросы **40±20 минут**
   - Максимум до **60 минут**

2. **Компьютер 2** обрабатывает **30 минут**

3. **Суммарное время:**
   - Оператор 3 + Компьютер 2 = ~40 + 30 = **70 минут** на запрос

4. **Накопление запросов:**
   - Оператор 3 медленно выдаёт запросы
   - Компьютер 2 не успевает обработать накопившиеся запросы
   - Очередь растёт до **115 запросов**!

**Парадокс:** Компьютер 2 загружен всего на 21.9%, но имеет огромную очередь!

**Объяснение:** Запросы приходят "пачками" от Оператора 3, который работает медленно и неравномерно (±20 мин разброс).

## 5. Ключевые особенности кода GPSS

### 1. Приоритет выбора операторов

```gpss
operator_1 GATE NU oper_1,operator_2
...
operator_2 GATE NU oper_2,operator_3
...
operator_3 GATE NU oper_3,fail
```

**Каскадная проверка** реализует приоритет:
1. Сначала пытаемся Оператора 1 (самого быстрого)
2. Если занят → пытаемся Оператора 2
3. Если занят → пытаемся Оператора 3
4. Если занят → отказ (fail)

**Это соответствует реальной логике:** клиенты хотят быстрого обслуживания.

### 2. Маршрутизация запросов к компьютерам

```gpss
TRANSFER,computer_1   ; От Операторов 1 и 2
TRANSFER,computer_2   ; От Оператора 3
```

**Разделение потоков:**
- Запросы от Операторов 1 и 2 → Компьютер 1
- Запросы от Оператора 3 → Компьютер 2

### 3. Вычисление вероятности отказа

```gpss
SAVEVALUE nfail,n$fail
SAVEVALUE prob,((n$fail)/(n$success + n$fail))
```

**Системная функция `n$метка`** — мощный инструмент для сбора статистики.

## 8. Формула вероятности отказа

**По результатам моделирования:**

```
P_отказа = n_fail / (n_success + n_fail)
P_отказа = 69 / (231 + 69) = 69 / 300 = 0.23 = 23.0%
```

**Это соответствует теоретической формуле для системы M/M/c/0** (система с отказами, без очереди):

```
P_отказа = P_0 * (λ/μ)^c / c!
```

где:
- λ — интенсивность входного потока
- μ — интенсивность обслуживания
- c — количество обслуживающих каналов (операторов)

В нашем случае система сложнее (разная производительность операторов, приоритет выбора), поэтому аналитический расчёт затруднён, и **моделирование — оптимальный подход**.
